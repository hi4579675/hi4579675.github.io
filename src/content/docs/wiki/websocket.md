**WebSocket** 은 하나의 TCP 연결 위에서 **양방향(full-duplex)** 통신을 지속하는 프로토콜이다. 실시간 채팅·알림·라이브 업데이트의 표준.

## HTTP 폴링과의 차이

- **Polling** — 클라이언트가 주기적으로 "새 거 있어?" 요청. 낭비 많고 지연 있음.
- **Long Polling** — 서버가 응답을 늦게 줘서 흉내. 여전히 연결을 매번 맺음.
- **WebSocket** — 한 번 연결하면 **서버가 먼저** 데이터를 밀어줄 수 있음(push). 헤더 오버헤드 없음.

## 동작

1. 클라이언트가 HTTP로 `Upgrade: websocket` 요청(핸드셰이크).
2. 서버가 `101 Switching Protocols`로 응답 → 이후 같은 연결을 WebSocket으로 전환.
3. 연결이 닫힐 때까지 양쪽이 프레임을 주고받음.

## 실무 메모

- 스프링에서는 보통 **STOMP**(메시지 프로토콜) + SockJS(폴백)로 다룬다.
- 수평 확장 시엔 서버 간 메시지 공유가 필요 → **Redis Pub/Sub**이나 메시지 브로커로 브로드캐스트.
