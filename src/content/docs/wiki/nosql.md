**NoSQL(Not Only SQL)** 은 관계형(테이블·조인·스키마) 모델을 벗어난 데이터 저장소의 총칭이다. 정해진 스키마 없이 대용량·고속·유연한 저장을 노린다.

## 등장 배경

대규모 트래픽과 비정형 데이터가 늘면서, 엄격한 스키마와 조인 비용을 가진 RDBMS만으로는 **수평 확장**과 **쓰기 처리량**을 감당하기 어려워졌다. 마이크로서비스로 가며 서비스마다 데이터 특성이 달라진 것도 한몫했다.

## RDBMS vs NoSQL

| | RDBMS | NoSQL |
|---|---|---|
| 스키마 | 고정 | 유연/없음 |
| 확장 | 수직(스케일 업) 중심 | 수평(스케일 아웃) 친화 |
| 조인 | 강점 | 보통 지양 |
| 일관성 | 강함(ACID) | 종종 결과적 일관성(BASE) |

## 4가지 유형

- **Key-Value** — 키로 값을 저장/조회. 가장 단순·빠름. 예: **Redis**, DynamoDB.
- **Document** — JSON 같은 문서 단위 저장, 필드 쿼리 가능. 예: MongoDB.
- **Column-Family** — 컬럼 묶음 단위, 대용량 쓰기에 강함. 예: Cassandra, HBase.
- **Graph** — 노드·간선으로 관계를 표현. 예: Neo4j.

> "무조건 NoSQL이 빠르다"가 아니라, **데이터 모델과 접근 패턴**에 맞는 저장소를 고르는 문제다. 트랜잭션·조인이 핵심이면 RDBMS가 여전히 맞다.
